01 · Persiapan aksesCentral Admin

Bagian A · Tugas Central Admin

Central Admin menyiapkan akun, memastikan role tersimpan dengan benar, dan memberi akses hanya ke event yang dimiliki komunitas.

  1. Pastikan migrasi role sudah diterapkan. Database harus menerima role RC_ADMIN pada user_event_roles. Migration 2026-10-02_add_rc_admin_scoped_role.sql sudah dijalankan pada environment yang akan dites.
  2. Buat akun komunitas khusus. Dari halaman Super Admin, buat user dengan role RC_ADMIN. Jangan beri role ADMIN; role itu membuka workspace operator yang lebih luas.
  3. Tentukan kepemilikan event. Disarankan RC Admin membuat event sendiri setelah login. Sistem akan mengaitkan pembuat dengan event. Jika central admin membuat event untuk komunitas, tambahkan assignment aktif RC_ADMIN pada event tersebut.
  4. Catat akun uji. Simpan email/kode login dan PIN/password melalui jalur aman. Jangan masukkan kredensial ke dokumen yang dibagikan ke umum.
Hasil yang diharapkan: user login dan diarahkan ke /rc-admin, hanya melihat event yang ditugaskan, dan tidak mendapat akses ke /admin.

Uji batas akses

  • RC Admin bisa membuka workspace dan melihat event miliknya.
  • RC Admin tidak dapat membuka workspace admin pusat dengan mengetik URL langsung.
  • Event milik komunitas lain tidak tampil dan endpoint event lain menolak akses.
  • Central Admin tetap bisa masuk ke Super Admin dan membantu semua event sesuai role pusatnya.
Jangan membagikan role central admin kepada komunitas. Jika RC Admin gagal membuka event sendiri, periksa assignment aktif dan role; jangan mengubahnya menjadi ADMIN sebagai jalan pintas.

Bagian B · Buat event sebagai RC Admin

  1. Login memakai akun RC Admin; buka /rc-admin.
  2. Pilih Buat event, isi nama event, tanggal, dan lokasi, lalu lanjutkan.
  3. Pastikan event baru muncul pada daftar event dan statusnya sesuai jadwal.
  4. Buka event untuk melihat ringkasan kesiapan dan tahapan setup.

02 · Setup eventRC Admin

Bagian C · Kategori dan aturan race

1. Kategori event

  1. Dari ringkasan event, pilih Kategori event.
  2. Gunakan sinkronisasi dari data rider bila roster sudah masuk; atau buat kategori secara manual.
  3. Periksa rentang tahun lahir, gender, nama kategori, kapasitas, dan status aktif.
  4. Pastikan tidak ada kategori ganda atau kategori yang salah rentang sebelum pendaftaran dibuka.

2. Aturan race

  1. Pilih Aturan race, lalu pilih kategori.
  2. Aktifkan multi-stage jika kategori memakai babak lanjutan.
  3. Atur jumlah maksimal rider per race dan jumlah moto kualifikasi.
  4. Isi batas rider repechage/QF/SF bila diperlukan; kosongkan untuk memakai default sistem.
  5. Ambang rider dimasukkan sebagai angka positif dipisahkan koma, misalnya 8, 16, 24.
  6. Isi override poin DNS/DNF hanya jika aturan event berbeda dari default.
  7. Simpan, lalu pilih kembali kategori untuk memastikan nilai tetap tersimpan.
Uji sebelum pendaftaran ramai: ambang jumlah rider menentukan format stage default yang dihitung sistem. Jangan mengira kolom ambang sebagai jumlah rider yang didaftarkan. Minta Race Director memeriksa rancangan aturan sebelum kategori dipakai.

03 · PendaftaranRC Admin

Bagian D · Buka dan review pendaftaran

  1. Bagikan halaman publik event/jadwal kepada peserta. Lakukan satu pendaftaran dummy terlebih dahulu dengan kontak dan rider uji.
  2. Dari ringkasan event RC Admin, buka Pendaftaran rider.
  3. Periksa data wali, nama rider, tanggal lahir, gender, komunitas, kategori, dokumen, dan bukti pembayaran.
  4. Jika ada kesalahan, minta koreksi sebelum menyetujui. Pastikan nomor plate tidak bentrok; sistem akan memeriksa ketersediaan dan memberi opsi suffix bila diperlukan.
  5. Setujui pembayaran dan pendaftaran sesuai kebijakan event. Saat approve, periksa bahwa rider terbentuk pada roster dengan kategori dan plate yang benar.
  6. Untuk pendaftaran tidak valid, reject dengan catatan yang jelas agar wali tahu apa yang harus diperbaiki.

Catatan operasional: halaman ini memakai workflow review yang sama dengan sistem pendaftaran yang sudah ada. RC Admin tidak memperoleh tombol hapus permanen pendaftaran; tindakan itu tetap dibatasi untuk admin pusat.

Titik kontrol sebelum drawing: jumlah rider yang disetujui cocok dengan roster; kategori dan plate benar; tidak ada pembayaran/dokumen yang masih menunggu keputusan tanpa tindak lanjut.

03 · Drawing & race dayHandoff saat ini

Bagian E · Handoff ke drawing

Drawing batch belum tersedia sebagai menu RC Admin. Untuk uji coba saat ini, central admin/operator melanjutkan pekerjaan melalui workspace drawing yang sudah digunakan sistem.

  1. RC Admin menyatakan roster final dan kategori siap. Jangan mulai drawing jika approval masih berubah-ubah.
  2. Central admin/operator membuka event pada workspace drawing yang sesuai, lalu memastikan kategori/rider yang dipilih benar.
  3. Tetapkan jumlah gate, pembagian batch/moto, dan mode drawing sesuai regulasi event.
  4. Jalankan preview dan pemeriksaan distribusi. Untuk manual draw, pastikan semua rider masuk tepat satu kali dan setiap batch tidak melebihi kapasitas gate.
  5. Simpan hasil drawing dan cek kembali moto, batch, gate, kategori, serta nama rider sebelum dipublikasikan.
Handoff bukan akses sementara ke /admin. RC Admin tetap memakai portal RC. Central admin/operator melakukan drawing hingga drawing manager khusus tersedia di portal komunitas.

Bagian F · Checklist race day

  • Pastikan daftar moto dan urutan race sudah diumumkan ke crew.
  • Checker memeriksa rider dan safety gear per moto; catat READY/ABSENT dan pelanggaran pada moto yang tepat.
  • Finisher memasukkan urutan finish dan mengirim hasil setelah race selesai.
  • Ikuti urutan event: selesaikan semua batch Moto 1 sebelum beralih ke Moto 2 batch pertama, kecuali format event secara resmi menetapkan lain.
  • Race Director menangani protes, DNS/DNF, penalty, safety review, dan keputusan tie-break berdasarkan aturan event.
  • Jangan membuat stage berikutnya sebelum hasil stage sebelumnya diverifikasi dan dikunci sesuai alur sistem.
  • Setelah seluruh race beres, verifikasi hasil final, klasemen, dan e-certificate sebelum memberi pengumuman publik.

Role crew seperti checker, finisher, dan Race Director memakai panel masing-masing. Jangan berbagi satu akun untuk beberapa petugas ketika sedang mengetes realtime.

05 · Uji cobaChecklist akhir

Bagian G · Uji coba end-to-end

Lulus jika

  • RC Admin hanya melihat event yang ditugaskan.
  • Perubahan kategori/rules tersimpan dan muncul setelah dimuat ulang.
  • Registration review dapat approve/reject dan hasilnya tercermin di roster.
  • Central admin/operator dapat meneruskan roster ke drawing tanpa duplikasi rider.

Hentikan tes jika

  • Event salah, kategori salah, atau jumlah rider tidak cocok.
  • Plate duplikat atau rider tampil di kategori yang keliru.
  • Aturan stage belum disepakati Race Director.
  • Hasil moto berubah setelah dikunci tanpa alasan dan audit.

Status panduan: ditulis berdasarkan kemampuan portal per 3 Oktober 2026. Drawing batch dan race-day operation khusus RC Admin adalah tahap pengembangan berikutnya; panduan ini menandai handoff secara eksplisit agar operator tidak mencari menu yang belum tersedia.
